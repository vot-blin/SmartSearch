# SmartSearch

Фронтенд на Vue и API на ASP.NET Core 8 в одном репозитории. PostgreSQL хранит пользователей и товары, Qdrant — поисковые векторы, OpenRouter анализирует запросы.

## Структура проекта

- `frontend/` — приложение Vue, клиент API, компоненты, страницы и хранилища состояния.
- `backend/` — приложение ASP.NET Core, контроллеры, сервисы и модели данных.
- `docker-compose.yml` — конфигурация контейнеров PostgreSQL, Qdrant и API.

## Требования

Потребуются Node.js ветки 22 версии 22.12 или новее, npm, .NET SDK 8 либо совместимый более новый SDK, а также Docker с Compose v2. Выполняйте команды ниже из указанного каталога.

## Запуск фронтенда

Из корня репозитория:

```powershell
cd frontend
npm ci
Copy-Item .env.example .env
npm run dev
```

Интерфейс в режиме разработки использует порт 5173. Значение `VITE_API_URL` по умолчанию — `http://localhost:5233/api`. Переменные Vite доступны пользователям приложения: не размещайте серверные секреты в файлах окружения фронтенда.

## Запуск бэкенда в Docker

Из корня репозитория:

```powershell
Copy-Item .env.example .env
# Укажите OPENROUTER_API_KEY в .env для анализа поисковых запросов.
docker compose up -d --build
```

API доступен на порту 5233, PostgreSQL — на 5432, Qdrant — на 6333/6334. Фронтенд запускается отдельно командами из раздела выше.

Имя проекта Compose явно задано как `smartsearch`: это сохраняет прежнее имя, которое по умолчанию определялось по каталогу `SmartSearch/`. Существующие тома сохраняют имена `smartsearch_postgres_data` и `smartsearch_qdrant_data`. Если ранее вы использовали `docker compose -p ...` или `COMPOSE_PROJECT_NAME`, продолжайте использовать то же имя проекта. Не выполняйте `docker compose down -v`, если нужно сохранить содержимое базы данных.

## Локальный запуск бэкенда

Из корня репозитория запустите только инфраструктуру:

```powershell
docker compose up -d postgres qdrant
```

Перед локальным запуском API остановите его контейнер, если он уже занимает тот же порт. Затем выполните следующие команды из каталога `backend/`:

```powershell
Copy-Item .env.example .env
# Укажите OpenRouter__ApiKey в backend/.env.
dotnet restore
dotnet run --no-launch-profile --urls http://localhost:5233
```

Сервер загружает `.env` из текущего рабочего каталога, поэтому запускайте его из `backend/`. Compose читает `.env` из корня репозитория. Существующие профили запуска IDE сохранены и используют порты 30086/30087. При их использовании настройте `VITE_API_URL` фронтенда на выбранный адрес API, включая суффикс `/api`.

Строки подключения и настройки JWT сохраняют прежние значения для разработки. Для своего окружения переопределите их переменными конфигурации, например `ConnectionStrings__DefaultConnection` и `Jwt__Secret`.

## Проверка

```powershell
# Из frontend/
npm run build
# Из backend/
dotnet build
# Из корня репозитория
docker compose config --quiet
```

При подключении к существующей настроенной базе данных проверьте регистрацию и вход, каталог, карточку товара, обычный поиск и AI-поиск. Для анализа запросов с помощью AI нужен ключ OpenRouter.
